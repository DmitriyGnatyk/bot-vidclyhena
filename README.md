# ⚡ Бот графіків відключень (РОЕ)

Telegram-бот, що стежить за графіком на roe.vsei.ua і тримає в чаті **картинку** з актуальним графіком.
Картинка міняється лише коли графік справді змінився, і тоді приходить сповіщення.

## Як малюється картинка
1. Бот парсить сайт кожні `CHECK_INTERVAL` секунд і рахує хеш даних.
2. Хеш не змінився — нічого не робимо (квота API не витрачається).
3. Змінився — бот будує HTML (`render.py`) і шле його в **screenshotbase.com** (`POST /v1/take`,
   елемент `#schedule`). Публічна адреса сторінки не потрібна — HTML летить прямо в запиті.
4. Готова картинка зберігається **одна на всіх** (файл `state_image.jpg` + `file_id` у `state.json`).

### `/grafic` не витрачає квоту
`/grafic` лише віддає вже готову картинку через `file_id` Telegram. Скільки б людей не тиснули
команду — до API нічого не йде. Якщо графік не змінювався, підпис покаже час *тієї* картинки
(наприклад «Оновлено 18.10 о 16:00»). Нову картинку знімають лише коли змінився графік —
один запит на всіх. Додатково `/grafic` не частіше ніж раз на 5 с з одного чату.

### Кілька ключів і текстовий режим
`SCREENSHOT_API_KEYS=ключ1,ключ2,ключ3` — ключі використовуються по черзі:
- `429 quota_exceeded` → ключ відкладається до дати скидання ліміту, береться наступний;
- `401/403` → ключ відкладається на добу;
- ліміт за хвилину / зайнятість → коротка пауза, наступний ключ;
- збій мережі/5xx → наступний ключ, а якщо впали всі — пауза 2 хв;
- усі ключі недоступні → бот шле й оновлює **текстову** версію. Щойно ключ ожив (скажімо, новий
  місяць), бот сам тихо замінює текст на картинку.

## Локальний запуск
```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # впиши BOT_TOKEN (Windows: copy)
python main.py
```

## Як тестити локально

**1. Тільки подивитись дизайн (без токена й бота)**
```bash
python render.py        # створить preview.html — відкрий у браузері
```
Міняєш CSS у `render.py` → знову `python render.py` → F5 у браузері.

**2. Дизайн на живих/демо-даних**
У `.env`: `DEMO=1` → запусти `python main.py` → відкрий `http://localhost:8000/view`.
(Без `DEMO=1` буде читати реальний сайт РОЕ.)

**3. Бот без ключів (текстовий режим)**
Нічого більше не додавай — у Telegram напиши боту `/grafic`, прийде текстовий графік.
Для перевірки автооновлення: `DEMO=1`, `DEMO_PERIOD=60`, `CHECK_INTERVAL=20` — дані міняються
щохвилини, бот сам оновлює повідомлення й шле сповіщення.

**4. Повний цикл з картинкою через screenshotbase**
Тунель більше не потрібен. У `.env`: `SCREENSHOT_API_KEYS=...` → перезапусти бота → `/grafic`.
(Sandbox-ключ повертає заглушку замість картинки — бот її відхилить, використовуй справжній.)

## Змінні середовища
Див. `.env.example`. Ключі `SCREENSHOT_API_KEYS` ніколи не комітити.

## Koyeb + UptimeRobot
- Web service, порт **8000**, health check HTTP `/health`.
- UptimeRobot: HTTP(s)-монітор на `/health`, інтервал 5 хв.

> `state.json` і `state_image.jpg` без volume живуть лише до перезапуску контейнера: після нього бот один раз знімає картинку заново (1 запит).
